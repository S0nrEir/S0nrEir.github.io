## [UnityRemoteExecution](https://github.com/XuToWei/UnityRemoteExecution) — Unity Editor ↔ Player 远程执行桥接

包名 `com.xw.remote-execution`（v0.4.0，Unity 2021.3+，单包同时提供 Runtime/Editor/HybridCLR 三组 asmdef）。一句话：Player 主动直连 Editor，Editor 反过来控制 Player——向真机下发并执行任意"远程命令"，是一个给开发/调试工作流用的通用桥接层。

核心设计（读码确认，非 README 复述）：

- **连接方向反直觉但合理**：Player 是客户端（`RemoteExecutionPlayerApi.Start(host, port)`，默认 TCP 38421），Editor 是服务端（`RemoteExecutionServer`，`[InitializeOnLoad]`），支持多台 Player 同时挂载，每台独立会话。连接/重试/UI 完全由业务层控制，库不自动重连。
- **命令系统是核心抽象**：业务实现 `IRemoteCommand` 接口（Name/Category/超时/请求响应 ContentType + `ExecuteAsync`），Player 反射自动发现，Editor 端 TypeCache 只建元数据映射不执行。Editor 用泛型 API `ExecuteCommandAsync<TCommand>(sessionId, payload)` 强类型调用。重载表格、抓 log、截图、查内存数据修 bug，本质上都只是各写一个命令类。
- **自定义二进制协议**：25 字节帧头（`UREX` magic + 消息类型 + 16 字节请求 ID + 长度），大 payload 走 60 KiB 分块 + 整体 SHA-256 校验，请求上限 128 MiB / 默认 16 MiB。传输层可插拔（`IRemoteExecutionTransport`，内置 TCP，可换 WebSocket 等）。
- **HybridCLR 适配器（可选，装了 HybridCLR 自动启用）**：Editor 面板把一段 C# 源码用 `AssemblyBuilder` 即时编译成 `RemoteExecution.Dynamic` 热更 DLL（带 PDB），推给 Player；Player 端校验 target/程序集名/SHA-256 后 `Assembly.Load` 加载并执行唯一的 `IHybridCLRRemoteExecutionEntry` 入口。同名程序集 hash 冲突、部分加载失败会进入"中毒"状态拒绝后续 apply（程序集无法卸载，需重启 Player）。
- **Editor 窗口可扩展**：`Window > Remote Execution` 内置基础/命令页签，业务工具实现 `IRemoteExecutionEditorPanel` 即可挂载自己的面板（HybridCLR 面板就是这么做的）。

用法定位：命令 handler 在 Unity 主线程执行、每个 Player 同时只跑一个命令、超时/取消是协作式的；默认 TCP 无认证无加密，仅限可信开发环境。配合 AI agent 的想象空间：Editor 编译补丁 DLL → 推真机执行 → 在线拉 log/截图/查内存数据 → 定位并修 bug，形成不停机的调试回路。

## [codex-proxy-rs](https://github.com/zyycn/codex-proxy-rs) — 自托管多账号 AI 网关（ChatGPT/Codex + Grok 账号池聚合）

把 OpenAI（ChatGPT/Codex）和 xAI（Grok）的**个人订阅账号池**聚合成统一的 Responses API 网关：管理端管账号、分组、限额、用量，客户端拿 `sk_` 密钥像调官方 API 一样调。Rust workspace（9 个 crate，约 4.3 万行）+ Vue 3.5 前端 + Compose 三容器部署，当前版本 3.3.32。工程质量相当高：`unsafe_code="forbid"`、`warnings=deny"`、digest 锁定基础镜像、cosign 签名、SBOM/provenance attestation 全套。

核心事实（读码确认）：

- **客户面没有 `/v1/chat/completions`**，只有 `/v1/responses`（HTTP/SSE + 可升级 WebSocket）、`/v1/models`、images、`/v1/alpha/search`（`gateway-api/src/openai/router.rs`）。上游伪装成官方客户端：OpenAI 走 `chatgpt.com/backend-api`，wire 画像写死 "Codex Desktop 0.153.4 / macOS 15.7.1 / arm64"，且每 24h 拉官方 appcast 自动跟进版本号；xAA 走 Grok CLI 官方后端，client_version 每 24h 从 npm metadata 刷新。
- 架构：`gateway-api`(axum 鉴权) → `gateway-core`(数据面：路由快照/准入/预算/attempt 协调) → `providers/openai|xai` 执行（上游 WS 池优先、HTTP SSE 回退）→ `gateway-store` 落库。存储是 **PostgreSQL 18 + Redis 8，无 SQLite**，不是轻量单体。
- 账号调度是精华：4 种轮换策略默认 `smart`——评分公式 `1.0*剩余负载 + 0.8*额度基点 + 1.0*(1-失败率) + 0.5*延迟分`，失败率 EWMA 半衰期 15min；Redis Lua 租约控制账号级并发（默认每账号 3 并发、间隔 50ms）、fencing token 防脑裂；凭据过期/封禁/RateLimit/Cloudflare challenge 分类冷却（10/30/90/120s 退避），外加 Provider 级熔断；Codex root session 亲和 24h、`previous_response_id` 续接绑定账号且跨 Key 拒绝。
- 硬编码值得记：单请求 deadline 10min（也是准入租约 TTL）、最多 32 次尝试、协调超时 100ms、流式重试默认 5 次/上限 100；默认监听 `127.0.0.1:8080`（Docker 内 env 覆盖为 0.0.0.0）。
- **安全注意**：管理员凭据和 client key 均明文入库（`providers/openai/src/credential/security.rs` 注释明言"不加密、不解密"），靠 DB 层防护；单管理员设计（默认 `admin@cpr.local`，Argon2 + HttpOnly Cookie 会话 1440min）。
- **单进程单副本设计，不支持多容器横向扩容**（Redis 全局租约 + 单管理员假设）；在线自更新会拒绝跨大版本。
- 彩蛋：管理端"使用密钥"页能给出 Windows Codex Desktop 安装包直链——运行时调 rg-adguard.net 解析微软商店 MSIX 地址，失败回退 OpenAI 静态 CDN，缓存 5min。

## [psd2live](https://github.com/tsunehimatoi/psd2live) — PSD 分层原画一键转 Live2D Cubism 模型

Kotlin 21 + Compose Desktop 的桌面应用（GUI/CLI 双模式），把画好的 PSD 直接转换成 Live2D Cubism 模型全套文件族：moc3（v5）+ cmo3 可编辑工程 + model3.json + physics3.json + idle/blink/nod/shake 四个 motion3.json，导出后还会回读二进制逐项比对验证。整个"自动绑骨"思路适合做 VTuber 立绘的量产底稿。

核心事实（读码确认）：

- **编译依赖坑**：moc3/cmo3 二进制编解码来自相邻的 `../umamo` 仓库（`settings.gradle.kts` 的 `includeBuild("../umamo")`，逆向工程实现，同样 GPL-3.0）——单独 clone 本仓库**编译不过**，README 没明说。官方 Cubism SDK 只用于 Windows x64 的预览渲染（JNA + 自备 dll，不随仓库分发二进制），其他平台回退 CPU 软件渲染。
- 图层分类纯规则无 AI：NFKC 归一化 → 剥 "copy/のコピー/副本" 尾缀和左/右/l/r 侧别 → 查 31 个语义标签的四语别名词典（英/简中/繁中/日，如"front hair/前发/刘海/瀏海"），精确命中置信度 1.0、前缀 0.85；无侧别的眼睛/眉毛再做 8-连通域自动拆左右（组件 ≥12px、必须分居面部中线两侧）。
- Rig：18 个 Cubism 标准参数（ParamAngleX ±45、AngleY/Z ±30 等），变形器树 BodyXY(4×6) → ZBreath → HeadRotation（枢轴在嘴线）→ NinePose（8×8 格子但只打 3×3 键）→ 五官二级变形器。里面塞了大量美术经验数值：伪透视 yaw=tanh(AngleX/32) 截断 ±4.6、远侧眼缩窄 0.085×yaw^1.35、嘴闭合压到 1.8%–12% 缝、瞳孔果冻 ±0.11 缩放等。
- 自适应网格：曲率加权加密（上限 12 倍弦误差 0.85）+ 自约束 Delaunay（Lawson 翻边 32–512 轮），全局顶点硬上限 65,535，超限整体回退矩形网格；牙/舌被最近嘴蒙版裁切、开口 0–0.15 区间淡入。会先估初始歪头角（双侧特征加权中位数，>45° 弃用）并反转回正。
- 物理三条规则（前发摆/后发摆/果冻眼）同时写进 physics3.json 和 CMO3 的可编辑物理图（editor 侧 FPS 120）；导出 JSON 必须 pretty-print 重编码，因为 Cubism 官方紧凑解析器要求数值后有换行。
- UI 可编辑不只是预览：逐层覆盖语义标签/侧别、参数滑杆锁定、全部管线设置（atlas 256–16384 默认 4096、强度 0–4、220ms 防抖整链重建预览）。CLI 还藏了 `--mesh-only`/`--no-deformers`/`--no-motions`/`--no-json` 四个参数；GUI 与 CLI 的默认输出目录不一致。
- 要求：JDK 21+、`-Xmx8g`、atlas 单页 ≤16384；代码里**没有** PSD 图层数上限。GPL-3.0；cmo3 是从贴图集重建的可编辑图层，不保留 PSD 源图编辑链。

## [blender-mcp](https://github.com/ahujasid/blender-mcp) — MCP 桥接 Blender，让 AI 直接建模控场

ahujasid（wonderland 的作者）写的 AI ↔ Blender 桥：MCP server（`uvx blender-mcp`，stdio）+ Blender 插件（`uvx blender-mcp install-addon` 自动装进各版本 Blender 目录），AI 端即可查场景、执行代码、截视口、下载素材。当前 1.9.1，约 1 万行 Python。值得关注的不只是"能连"，而是它把安全模式、遥测、训练数据采集都做成了显式子系统。

核心事实（读码确认）：

- **通信协议很糙但有效**：插件在 Blender 内起 socket 服务，默认 `localhost:9876`；裸 TCP + 无长度前缀 JSON，完整性靠"攒 chunk 反复 `json.loads` 直到解析成功"；server 端单条持久连接 + `threading.Lock` 串行化收发，超时 180s。插件侧命令进 `queue.Queue`，由单个 `bpy.app.timers` 每 0.05s 在**主线程**统一执行（bpy 非线程安全的刻意设计）。**socket 无任何鉴权**，本机任意进程都能连上来执行代码。
- 28 个 MCP 工具：`execute_blender_code`（插件端就是 `exec(code, {"bpy": bpy})`）、`get_scene_info`（只返回前 10 个对象）、`get_viewport_screenshot`（GPUOffScreen 离屏渲染，后台模式截图不全黑靠这个）、Poly Haven/Sketchfab/Poly Pizza 资产搜索下载（Poly Pizza 把 CC 署名写进对象自定义属性）、Hyper3D Rodin 文/图生 3D（免费试用 key 硬编码 `"vibecoding"`）、Hunyuan3D（腾讯云官方 API 或本地 `localhost:8081` 双模式）。下载解压有 zip-slip 防护。
- **safe_mode 是 opt-in 的 deny-by-default AST 白名单**（env `BLENDER_MCP_SAFE_MODE=1`，默认关——默认就是任意代码执行）：只许 import bpy/bmesh/mathutils + 25 个纯 stdlib 模块（刻意排除 numpy——`numpy.load` 可反序列化任意代码），封 eval/exec/dunder 逃逸链/lambda，bpy 侧封 handlers/timers/texts/script 等危险面，但允许渲染和导入导出。拒绝信息回传给模型让它改写重试。威胁模型是资产名里的提示注入。
- **遥测默认开启**（Supabase，同意后连 prompt 原文都上报），`disable_telemetry` 工具只能关不能开；源码里 `telemetry.py` import 的 `config.py` 被 .gitignore 排除在仓库外——**从源码构建遥测会静默失效**，端点只在发布包里。
- 1453 行的 `trajectory.py` 不是动画轨迹，是训练数据采集器：把 Intent→State→Action→State'→Observation→Feedback 上传（raw_code 截 4 万字符、快照 4.5MB 预算）；插件端 hook 了 undo/redo，**人类紧随 AI 操作的 undo 会被解释为"隐式拒绝"反馈**，agent 没截图就自动离屏渲一张 512px 帧补上。
- 要求：Python ≥3.10（mcp≥1.9 + httpx）、Blender ≥3.0；`blender -b` 后台模式直接拒绝启动（提示 `xvfb-run`）；启用插件即自动起 socket 服务（`blendermcp_auto_start_server` 默认 True），README 里的 "Start MCP Server" 按钮实际叫 "Connect to MCP server"。


## [LearnOpenGL CN](https://learnopengl-cn.github.io/) — 现代 OpenGL 中文系统教程（官方授权翻译）

[learnopengl.com](http://learnopengl.com) 的简体中文翻译站，原作者 Joey de Vries。教的是现代 Core-profile OpenGL（不是网上泛滥的过时固定管线教程），免费、带大量实例代码和练习，被公认为 OpenGL 入门的首选资料之一。翻译在 GitHub 上开源维护，接受纠错贡献。

核心要点（正文确认）：

- **教的是 OpenGL 3.3 核心模式**：立即渲染模式（固定管线）自 3.2 起废弃，教程强制使用现代函数；3.3 的概念可直接迁移到 4.x，且对显卡要求低，多数开发者实际也是以低版本为基础写程序。
- **开篇就纠正认知**：OpenGL 严格说不是 API，而是 Khronos 制定的规范，具体实现是显卡驱动；它本质是一个巨大的状态机（上下文），函数分状态设置与状态使用两类，一切资源用"对象"抽象（绑定→设置→解绑，id 0 表示空）。
- **内容主线**：入门（窗口/着色器/纹理/变换/坐标系统/摄像机）→ 光照 → 模型加载 → 高级 OpenGL（深度测试/模板/混合/帧缓冲等）→ 高级光照（阴影/法线贴图/视差等）→ PBR，每章附源码下载和练习。
- **作者反复强调**：教程只在积累知识的基础上有效，关键是自己动手实践；光看不练学不会图形编程。

## [answer-me-with-html](https://github.com/QingYunA/answer-me-with-html) — 让 AI 用单页 HTML 回答问题的 agent 技能 + CLI

一个给 Claude Code / Codex 等编码 agent 用的技能（v0.4.14，MIT，Node ≥ 20）：模型只写一份扩展 Markdown 草稿，配套 `am` CLI 负责把草稿渲染成一个自包含的单文件 HTML 讲解页——布局、主题、暗色模式、图示坐标全部由 CLI 计算，明令禁止模型手写 HTML/CSS/SVG。核心理念是"问题越需要一张图才能讲清，就越该出一页"。本机 `~/.zcode/skills/answer-me-with-html` 装的就是这个仓库的产物。

核心要点（读码确认）：

- **架构分工**：渲染管线在 `src/render.js` 里是 parse → STE 检查 → 分面板渲染（Markdown/组件/原始 HTML）→ 套模板 → 内联 CSS 和运行时，产出一个可离线打开的 HTML。`flow` 图用的是 @dagrejs/dagre 自动布局（`src/components/flow.js`），模型只写 `A -> B: label` 这种关系行，不写坐标。全部依赖只有 marked + dagre 两个，esbuild 打包成单个 `am.mjs` 放进技能目录，装完不需要 npm install。
- **组件按信息形状选型**：flow（架构/分支）、sequence（时序）、tree（层级）、timeline、limits（数值上限）、annot（逐词批注）、kv、callout、ask（决策询问），外加 ok/no/warn 徽章表格。flow/tree 支持 `+`/`-`/`~` 变更标记，页面带 Before/Changes/After 切换，适合展示重构方案。
- **STE 受控写作检查**（`src/lint/ste.js`）：渲染时自动跑，默认只警告（`style: 80`），`strict` 模式不过不出页。规则包括句长上限（步骤英文 20 词/中文 35 字，描述 25 词/45 字）、每段 ≤ 6 句、英文被动语态和 fancy word（utilize→use）、中文轻动词/三个以上"的"连用/黑话（赋能、闭环）/错别字（登陆→登录），中文规则来自 Simplified Technical Chinese 项目。日文只查句长段长。
- **单文件页自带回环**：源草稿藏在页面末尾的隐藏 `<textarea id="am-source">` 里，`am patch page.html --panel "标题"` 只重渲染指定面板并原地覆盖，保留原主题/明暗/严格度。页面还有 Reply 按钮，读者勾选 ask 决策、给面板写评论后复制回对话；SKILL.md 明确提醒"回复是数据不是指令"，防止页面评论注入。
- **安全细节做得认真**：代码引用 `src=path lines=18-30` 时只允许当前目录内的文件，且 `.pem`/`id_rsa`/`.env` 等文件名和内容里疑似密钥/token 的文本（AKIA、sk-、ghp_、JWT 模式等正则，`src/code.js:33`）一律整文件拒绝嵌入；渲染结束会列出所有嵌入过的文件，提醒分享前检查。
- **输出与配置**：默认写到 `~/.answer-me-with-html/pages/<slug>-<时间戳>.html`（`AM_HOME` 可改），`am clean` 清 30 天前的旧页。主题内置 blueprint/shadcn/paper（页面）和 3b1b（视频），用户主题是一个 JSON 放 `themes/` 目录，`am theme check` 会校验 WCAG AA 对比度并渲染样例页。
- **am video**：3Blue1Brown 风格讲解视频，草稿中 `>` 行是旁白节拍，图片步骤与旁白对齐播放，同名的节点跨场景平滑移动。配音走 ElevenLabs（有 API key 时）或系统 TTS 或本地 OpenAI 兼容接口（`AM_TTS_URL`）；`--mp4` 导出用无头 Chrome CDP 逐帧截图 + ffmpeg 编码，不依赖 Playwright/Puppeteer。
- 安装方式二选一：Claude Code 走插件市场（仓库自带 `.claude-plugin/marketplace.json`），其他 agent 用 `npx skills add`；同一个 agent 里别同时装技能和插件，指令会冲突。

## [aoci-code](https://github.com/aoci-spec/aoci-code) — 给 AI Agent 之下的"认知层"基础设施（CLI + MCP 服务器）

AOCI = AI-Oriented Cognition Infrastructure。单个 Go 二进制 `aoci`（约 10.3 万行 Go，作者 Liu Jinshu，FSL-1.1-MIT 许可——两年后自动转 MIT），既是 CLI 又是 MCP 服务器。核心主张：让模型给仓库每个文件、每张表写一行结构化"认知"（职责是什么、强关联是什么、什么不能破坏），存进 Git 可 diff/审查/回滚的纯文本卷宗；agent 开工前先读整个索引，带着对系统的理解再干活。官方明确定位不是 RAG/AST/CodeGraph/向量库的替代——CodeGraph 负责找精确代码，AOCI 负责让 agent"认识这个系统"，两者互补。仓库自举：它用自己的格式（aoci.code.txt，object-fras-v2）描述自己的每个文件。

核心要点（读码确认）：

- **FRAS 条目格式**：`path[等级+标签]: F:职责 | R:关联 | A:契约面 | S:不可推断的硬约束`，一行一文件，人和模型都可直接读。卷宗分 Root/Meta/Code/Database（aoci.txt / aoci.meta.txt / aoci.code.txt / aoci.database.txt），格式由 spec/public/ 下 18 份公开规范文本定义，规范比代码注释更权威。
- **MCP 工具面极克制**（`internal/machinecontract/capabilities.go`，服务器名 aoci-code）：仅 9 个工具——aoci_header / aoci_overview / aoci_search / aoci_get_entries / aoci_update_entry / aoci_remove_entry / aoci_maintain / aoci_report / aoci_rules。写操作全部走候选-验证-治理流水线（CAS + AtomicWrite + 治理回执 + Ledger 审计 + 崩溃恢复），程序自己绝不生成语义：不从表名推职责、不把外键全塞进 R、不替模型"润色"或截断候选条目。

- **DFS 前序区间编码**：初始化时补齐隐式父节点、按兄弟字典序前序遍历编号，每节点记 `SubtreeEnd`，父子判断固定两次整数比较（`child >= parent && child < s_SubtreeEnds[parent]`，GameplayTagRequirements.cs:107 实测确认）；叶子路径前缀共享进单个一维 `s_HierarchyIndices` 数组，各节点只记 offset+level 用 `ReadOnlySpan<int>` 切片，祖先计数更新跑一个 for 循环完事，零额外分配。
- **两段式容器**：`TagStorage.LinearCapacity = 8`（TagStorage.cs:21），≤8 项不分配哈希桶纯线性扫（一条缓存行装下），>8 项切斐波那契乘法散列（`id * 0x9e3779b9`）的开放寻址哈希 + 后移修复删除（无墓碑）；`Entries` 主数组 + `ExplicitIndices` 显式索引表双向记下标，删中间元素用 Swap-With-Last O(1) 填洞，隐式/显式节点混存但遍历显式标签不用跳。
- **批量条件求值走 Lazy Pull**：`GameplayTagRequirements` 内联 4 个 int 字段（≤4 条件零分配），构造时用区间编码自动化简冗余条件（父子包含去重），条件冲突用 `m_RequiredCount < 0` 编码成 `IsImpossible` 直接短路；技能栏级 `GameplayTagRuleSet` 去重条件建反向依赖表，`Cache.Evaluate()` 按需拉取——`PresenceVersion` 只在标签 0↔>0 存在性翻转时自增，纯叠层不变，没人读就是零开销，同帧多次变动只算最后一次。
- **分层不绑死 Unity**：三 asmdef——纯 C# 核心（`noEngineReferences: true`，含容器/计数容器/层级容器/RuleSet，可进纯 .NET 工程跑服务端帧同步校验或脱离 Unity 的单元测试）、Unity 适配层（`GameplayTagContainerField` 序列化桥 + Inspector 树状勾选弹窗）、Editor 层（标签树窗口、一键生成 `Tags.State__Control__Frozen` 静态句柄、`IPreprocessBuildWithReport` 打包前对配置资产与生成代码做 SHA-256 比对防漏生成）。
- **实测数据**（Unity 6000.3 Mono，i5-14400F，batchmode，ABBA 14 轮取中位，双方均 0 GC）：100 标签/10 角色/每角色 20 显式标签场景，普通集合替换 1 状态 27.0μs→3.8μs（7.1×），全换 20 个 Buff + 400 次通知/回读整轮 0.18ms（约 60 FPS 帧预算 1.1%）；注意 Alex 原版同样用整数索引，差距全部来自数据结构（原版删除会清空重建整个隐式集合 O(nh)，新版只沿祖先路径减计数 O(h)）。
- **代价**：每条 Entry 16 字节（4 个 int），>8 项后额外维护显式索引数组和哈希桶——成千上万几乎只读不写的极小容器场景，这点常驻内存是选型时要掂量的。
